Web QR linking: test sheet

Backend ticket BE-6.1. Takes about 15 minutes. You need a PC, an Android phone and a test account.

What you are testing

Web shows a QR code. A logged-in phone scans it. The backend then pushes the login to Web, with no polling. Log out and "one Web session per account" are also checked.

Before you start: ask Mervin for

  • The backend URL (an https://….trycloudflare.com address). It only works while his PC and tunnel are running.
  • A test account that can log in on the phone. Do not use a real person's account.
  • The project zip: INFRA_backend-FULL.zip (backend, phone app and Web in one folder).
Read this first.
  • This backend is connected to the real Supabase database. Your tests create and end real rows in devices and sessions.
  • The tunnel address is public. Only share it with the team, and ask Mervin to close the tunnel when testing ends.
  • Never share or commit the backend .env file.

Step 1: Run Web on your PC

Unzip the project, then in PowerShell (use your own URL):

cd INFRA_backend\sealine-web-mervin-style
pnpm install
$env:API_BASE_URL="https://THE-URL-MERVIN-GAVE-YOU"
pnpm --filter "@wpt/web" dev

Open http://localhost:3000. Use exactly this address. The backend only allows this origin, so a different port or a LAN IP will fail on log out and refresh.

Expected: a QR code with a countdown from about 60 seconds.

Step 2: Get a phone that can scan

Option A (real app). The phone-app changes are already inside apps/mobile. Run pnpm install once in the INFRA_backend folder, then create apps/mobile/.env containing:

EXPO_PUBLIC_BACKEND_URL=https://THE-URL-MERVIN-GAVE-YOU
cd INFRA_backend\apps\mobile
npx expo start -c --tunnel

This project uses Expo SDK 54, so the newest Expo Go from the Play Store will refuse it. Plug the phone in by USB (USB debugging on), uninstall Expo Go, then press a in the Expo window. Expo installs the matching Expo Go. Log in, then open Settings and tap Scan QR Code.

Option B (no phone app). Get a phone access token for the test account and simulate the scan:

$env:PHONE_ACCESS_TOKEN="<phone access token>"
node sealine-web-mervin-style\scripts\phone-scan.mjs '<paste the QR text>'

Optional: check the database

In the Supabase SQL Editor (read only):

select id, device_type, linked_at, revoked_at
from devices
where device_type = 'web'
order by linked_at desc
limit 5;

After Log out, or after linking a second browser, the older row has a time in revoked_at. Do not edit or delete rows.
